# Optional VLA / world-model profile

Use for VLA, world-action models, manipulation and representation/control questions.
Keep the core workflow general. Exclusions belong to the user's brief or private profile.
Do not embed unpublished ideas, identities, private paths or server configurations.

Before feasibility claims verify code, weights, data access, train/eval scripts and each
license. OpenWAM, LIBERO and RoboTwin are optional names to investigate, not verified
recommendations. Check their current architecture, entrypoints and resource needs using
permitted primary sources. Hardware is unknown until the user supplies it.

When appropriate, freeze large backbones, cache features and use probes, small modules
and inference interventions. These are cost-saving defaults, not universal requirements.
Check five confusions: prediction quality versus action sufficiency; linear readability
versus actual policy use; open-loop scores versus closed-loop success; training supervision
versus inference computation; and extra data/information leakage versus fair comparison.

A useful conditional chain is cheap diagnostic → causal intervention/necessity check →
minimal module → closed-loop evaluation. At each transition specify an observation for
and against the core hypothesis, and the resulting decision. If intervention disproves
the mechanism, do not train a bigger model to obscure the failure.
